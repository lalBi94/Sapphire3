## Transpilation C expérimentale — 11 novembre 2026

- Un backend **C** expérimental est ajouté dans `src/utils/transpilation/c.js` et enregistré dans `transpilationLanguages` et `backends`. La cible est volontairement restreinte : primitives numériques, booléens, chaînes, fonctions, paramètres, blocs, conditions, boucles, `break`/`continue`, affectations, opérateurs, littéraux, références, appels, `Print`, pointeurs `&`/`*` et lambdas sans capture. Les tableaux, classes, lambdas capturantes, `ForEach`, `MathCall`, conversions explicites, `char`, variables sans initialiseur et adresse d'une constante sont refusés avec `TRANSPILE_C_UNSUPPORTED` avant émission.
- Le code généré est un fichier C11 unique avec `main`, prototypes de fonctions, déclarations globales et initialisation dans l'ordre topologique. Les helpers `sapphire_iadd`/`isub`/`imul`/`idiv`/`imod` et `sapphire_uadd`/`usub`/`umul`/`udiv`/`umod` contrôlent les bornes et les divisions par zéro ; les helpers `f32`/`f64` vérifient les infinis, les sous-flux et les divisions par zéro. `Print` formate les entiers, booléens et chaînes ; les flottants passent par un formateur décimal qui cherche la représentation la plus courte qui round-trip, avec normalisation de l'exposant.
- Les pointeurs C sont natifs : `&variable` et `&paramètre` produisent un pointeur typé, `*p` lit et écrit la valeur. Les chaînes sont des `const char *` UTF-8 ; l'égalité utilise `strcmp`, les textes contenant NUL ou un surrogate isolé sont refusés.
- Les pointeurs de fonction **nommés** sont pris en charge via des typedefs C : paramètres, variables, retours et appels via une référence nommée. Les **lambdas sans capture** sont levées en fonctions statiques `sapphire_lambda_N` et utilisées comme pointeurs de fonction ; une lambda qui capture une variable locale ou un paramètre est refusée. `Print` d'un pointeur de fonction reste refusé.
- Vérifications : **676 tests Node/Python réussis**, dont 11 tests C dédiés (primitives et `Print`, fonctions/conditions/boucles/globales, boucle `for`, pointeurs, pointeurs de fonction nommés avec Higher-order, variable de type fonction et retour de pointeur de fonction, lambda sans capture passée à une fonction d'ordre supérieur, refus d'une lambda capturante, débordement contrôlé, refus explicites, sélection). Build Vite réussi. Les fichiers C générés pour Fibonacci, Recursion, Imports, Pointers, Higher-order et Calculus sont compilés avec `cc -std=c11` et exécutés ; leur sortie correspond au simulateur. Contrôle navigateur : l'exemple Fibonacci affiche **C Transpilable**, le panneau C montre le code et **Export .c** ; le modèle Classe + instance affiche **C Not transpilable**.
- Limites : pas de tableaux, classes, lambdas capturantes et fermetures, `ForEach`, opérations natives, conversions explicites, `char` ni variables non initialisées. Les lectures de globales avant leur initialisation ne sont pas détectées (C les initialise à zéro). Un pointeur vers une variable locale ne doit pas survivre à sa fonction. Le formatage des flottants extrêmes peut différer de JavaScript. La cible n'a pas été exercée dans la fenêtre Neutralinojs.
- Documentation publique : nouvelle page `abstract/visual/transpilation.html` (matrice de périmètre et correspondances), lien depuis la navigation des pages documentaires et la passerelle d'accueil, entrée dans le catalogue de recherche (38 destinations), sous-section 7.1 dans `abstract/ARCHITECTURE_AST.tex` (PDF recompilé en 9 pages sans avertissement), page **Transpilation** du wiki et liens de navigation. Vérifications : `pnpm site:search`, `pnpm site:test`, `pnpm docs:ast`.

## Transpilation des classes — 11 novembre 2026

- Les backends **JavaScript** et **Python** génèrent désormais les modules `kind: 'class'`. Une classe devient une `class` JavaScript ou Python avec ses champs par instance, son constructeur et ses méthodes ; `this` devient `this` en JavaScript et `self` en Python. Les modules de classe ne sont plus initialisés comme des modules ordinaires : leurs champs ne deviennent pas des globales.
- Les initialiseurs de champs sont passés au constructeur comme paramètres techniques, ce qui les évalue dans la portée du `new`, comme le simulateur. Les champs sans initialiseur conservent `sapphireUninitialized` et une lecture échoue avec `SIMULATION_UNINITIALIZED`.
- Les méthodes sont marquées côté JavaScript pour que `sapphireMember` renvoie une méthode liée lorsqu'elle est utilisée comme valeur (callback `ForEach`, attribut fonction). Python utilise naturellement ses méthodes liées. Les noms de classes et de membres sont normalisés et réservés par langue ; les collisions internes à une classe sont désambiguïsées.
- `sapphireFormat` formate les instances comme le simulateur (`ClassName { champ: valeur }`), y compris les tableaux et les champs imbriqués. La visibilité public/private reste une règle d'analyse : le code généré utilise des propriétés ordinaires et ne crée pas de barrière runtime.
- Les sélections de module ou de membre de classe produisent la définition complète de la classe ; les autres sélections gardent leur comportement.
- Vérifications : **665 tests Node/Python réussis**, dont 13 tests de classes (instanciation, constructeur, champs, méthodes, `this`, lecture non initialisée, callback `ForEach`, méthode liée stockée, `Print` d'une instance, sélection de classe). La suite utilise `--test-concurrency=4` pour éviter la saturation des processus Python pendant les tests de transpilation. Build Vite réussi. Les fichiers générés pour le modèle **Classe + instance** s'exécutent avec Node et Python et produisent la même sortie que le simulateur.

## Classes, scopes et instances — 7 novembre 2026

- Une classe est un module `kind: 'class'` dont la racine n'accepte que des attributs, des constantes, des méthodes et un constructeur. Les deux scopes **Public** et **Private** sont portés par `properties.visibility` sur chaque membre ; l'arbre de la carte les affiche séparément et chaque scope a son propre bouton d'ajout.
- Le constructeur est une `FunctionDeclaration` avec `properties.constructor: true`, nommée `constructor`, de retour `void`, unique et sans point d'entrée. Le formulaire dédié ne montre ni nom, ni type de retour, ni point d'entrée, ni paramètres de type ; il conserve les paramètres et la visibilité.
- Nouveaux nœuds `NewExpression`, `ThisExpression` et `MemberExpression`. `NewExpression` porte `classId` et les arguments du constructeur ; `ThisExpression` n'est admis que dans une méthode ou un constructeur ; `MemberExpression` lit un attribut ou appelle une méthode. `CallExpression` accepte un `MemberExpression` comme callee, et `AssignmentStatement` accepte un `MemberExpression` comme cible.
- Le type `{kind:'class', classId}` est annotable sur les variables, constantes, paramètres, retours et signatures de fonction. Les tableaux et pointeurs de classes restent refusés. Les membres privés et les constructeurs privés sont contrôlés à l'analyse ; un accès privé hors de sa classe produit `TYPE_MISMATCH`, `this` hors méthode produit `PLACEMENT_ILLEGAL`.
- La simulation crée l'instance, initialise les attributs, exécute le constructeur puis lie `this` aux appels de méthodes. Les modules de classe sont ignorés lors de l'initialisation globale. Les objets s'affichent sous la forme `Classe { champ: valeur }`.
- La transpilation JavaScript/Python refuse toute source contenant une classe avec `TRANSPILE_CLASS_UNSUPPORTED`, en attendant une génération d'instance dédiée. L'interface de module (exports/imports) est masquée pour une classe, et les favoris ne proposent plus une classe comme destination.
- `pnpm test` : **555 réussis** (+6 dans `tests/logic/classes.test.js` : instanciation/constructeur/attributs/méthodes/`this`, aller-retour workspace, refus de transpilation, accès privé hors classe, instruction libre refusée dans une classe, `this` hors méthode). `pnpm build` réussi.
- Contrôles navigateur : carte Class avec scopes Public/Private, menu limité aux variables/fonctions/constructeur, formulaire Constructeur sans nom/retour/point d'entrée, visibilité privée conservée, type de classe proposé dans le sélecteur, formulaire `NewExpression` avec classe et arguments. ## Adoucissement de la jauge — 6 novembre 2026

- L'anneau de la carte **Gauge** rejoint sa nouvelle valeur par un lerp bref au lieu de sauter : le facteur est corrigé du temps écoulé (`1 - 0.62^(ms / 16,7)`), ce qui garde le même ressenti si le rendu ralentit, sans jamais dépasser la cible. La convergence mesurée est monotone : 38 % du trajet après une image, 91 % après cinq, 99 % après dix, stabilisation complète en **13 images (≈ 217 ms)** à 60 fps.

La boucle `requestAnimationFrame` s'arrête d'elle-même au seuil de 0,2 % et son nettoyage l'annule au démontage ou à un changement de cible. `prefers-reduced-motion: reduce` rétablit un saut immédiat.
