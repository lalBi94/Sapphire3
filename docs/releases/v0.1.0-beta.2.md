# Sapphire 3 Beta 0.1.0-beta.2

Deuxième **bêta** Windows de Sapphire 3. Elle regroupe les évolutions depuis la bêta `0.1.0-beta.1` : généricité avancée, **lambdas et fermetures**, cartes spéciales Screen/Gauge/LED, contrats vérifiables enrichis, nouveaux exemples, récupération des documents non enregistrés, moteur hors du fil React, gestionnaire de fenêtres et optimisations de rendu.

Cette version reste une **bêta** : le format des workspaces et le moteur peuvent encore évoluer. Les mises à jour sont recherchées dans les releases **publiées** du dépôt GitHub et installées après confirmation.

## Nouveau depuis la bêta 0.1.0-beta.1

### Langage
- **Lambdas et fermetures** : une expression anonyme peut déclarer des paramètres typés et une expression de résultat, capturer les variables visibles par référence et être stockée, passée en argument, utilisée dans `ForEach` ou appelée immédiatement. Une fonction peut désormais retourner un type fonction, ce qui permet de renvoyer une fermeture qui survit à la sortie de sa fonction. JavaScript émet une fonction fléchée, Python une `lambda`.
- **Généricité avancée** : une fonction peut déclarer plusieurs paramètres de type `T`, `U`, etc., chacun avec une **contrainte exacte optionnelle**, et les utiliser directement ou comme **tableaux génériques** (`T[]`). L'inférence confronte chaque argument à son motif, exige le même type pour toutes les occurrences, vérifie la contrainte et substitue le retour. Aucune spécialisation : la simulation et les backends JavaScript/Python utilisent la même fonction ordinaire.
- **Initialisation globale ordonnée** : les modules sont initialisés dans un **ordre topologique stable** selon leurs références importées ; un module consommateur passe après ses fournisseurs, l'ordre source départage les modules indépendants et sert de repli en cas de cycle. La simulation et les backends JavaScript/Python partagent cet ordre.
- **Pointeurs transpilés** : `&`, `*p`, `*p = valeur`, les paramètres pointeurs et l'égalité d'adresses sont émis en **JavaScript et Python** par émulation portable (cellules et objets d'adresse). La constance, les cases de tableau et les échanges par pointeur restent protégés. C, C++ et Java restent indisponibles.

### Cartes spéciales Screen, Gauge et LED
- **Screen** : carte pixel reliée à un module caché normal, API `SCREEN_SP3_*` (`SET_PIXEL`, `GET_PIXEL`, `SET_WIDTH`, `SET_HEIGHT`, `BLIT`, `PRESENT`), lecture des images à **24 fps** et vue **code du module**.
- **Gauge** : anneau gradué avec dégradé du thème, API `GAUGE_SP3_*` (`SET_VALUE`, `ADD_VALUE`, `GET_VALUE`, `SET_RANGE`, `RESET`, etc.), vue **aperçu / code** et valeurs synchronisées avec les images d'écran.
- **LED** : voyant booléen avec halo, API `LED_SP3_*` (`SET_VALUE`, `GET_VALUE`, `TOGGLE`) et vue **aperçu / code**.
- Les trois cartes participent aux **flèches de dépendance** vers les modules qui utilisent leurs fonctions exportées, avec le détail des exportations dans l'infobulle.
- Les vues d'écran, de jauge et de LED sont des préférences de présentation conservées dans le `.sp3` (`screenView`, `gaugeView`, `ledView`) et refusées à l'import si leur valeur est inconnue.

### Contrats vérifiables
- Catalogue de **20 contrats** pour les nombres (signe, parité, seuils, intervalle), les chaînes (blancs, ligne unique, préfixe/suffixe, contenu, longueur), les tableaux (unicité, tri) et les booléens.
- Les contrats à paramètre demandent une valeur numérique ou un texte ; une borne inversée ou un argument vide est refusé.
- Le sélecteur ne propose que les contrats **applicables au type déclaré** : entiers, flottants, chaînes, tableaux et booléens ; aucun contrat pour les pointeurs et les fonctions.
- Pendant **Run**, les violations sont signalées avec le nom, la règle, ses paramètres, le pas et la valeur observée, sans interrompre le programme.

### Exemples
- Le catalogue compte désormais **20 exemples** classés Simple, Medium et Hard, dont **Car dashboard**, **Bouncing logos**, **Matrix rain**, **Game of life**, **Knapsack**, **Calculus**, **Quick sort**, **Coin change**, **Rover survey** et **Signal lab**.
- **Rover survey** : carte 48×18 avec rochers, batterie, pointeurs, contrats, jauge et LED. La cible de l'artefact est tirée aléatoirement dans une bande haute ou basse ; le rover avance de deux cases par image et change de destination à chaque **Run** comme à chaque **boucle de lecture**.
- **Signal lab** : statistiques, texte, tableaux et natives mathématiques sur une courbe animée.
- Les animations d'écran **sans cycle** relancent désormais la simulation à la fin de leur lecture pour renouveler les images ; les animations cycliques (pluie, jeu de la vie, logos) continuent de boucler.

### Données
- **Récupération après crash** : un document neuf non vierge reste protégé par une copie `sapphire3-recovery.sp3` et restauré au prochain lancement.
- **Sauvegardes de secours** : chaque enregistrement direct d'un `.sp3` existant conserve jusqu'à trois versions précédentes (`<base>.backup-1.sp3` à `3`) avant l'écriture atomique. Une copie impossible n'annule pas la sauvegarde ; elle est affichée comme message de statut, sans bloquer le canvas. L'absence d'une génération est normale et ne produit plus d'erreur.
- **Format versionné** : le workspace passe en **version 2**. Les fichiers version 1 sont migrés à la lecture (`generic` → `typeParameters`, retrait de `screenScale`) ; les versions futures ou malformées sont refusées sans remplacer le document courant.

### Interface et rendu
- **Zoom sémantique** : les instructions restent détaillées au-dessus de **21 %** ; de **10 à 21 %**, chaque module affiche seulement ses fonctions racines avec leur signature ; à **10 % et moins**, seules les cartes de modules et leurs relations subsistent. Un badge indique le niveau courant et une recherche de bloc force le détail.
- **Moteur hors du fil React** : simulation, préparation du debug, transpilation et vérifications de cibles s'exécutent dans un **Web Worker**. Un panneau compact affiche l'avancement (phases d'analyse, pas de simulation, génération) avec un bouton **Cancel** qui **termine immédiatement le worker** et invalide les résultats en attente. Les relances d'écran ne transfèrent que les images utiles, et les panneaux de propriétés limitent les rendus pendant l'animation.
- **Debug compact** : les états d'écran sont enregistrés en **image de base + pixels modifiés**, les liaisons inchangées sont partagées et la sortie est réutilisée. Le debug de **Rover survey** conserve ainsi **1 583 arrêts** au lieu de s'arrêter à 63, sans changer la navigation ni la mémoire affichée.
- **Gestionnaire de fenêtres** : volet **Windows** listant les fenêtres ouvertes, avec focus, pliage, fermeture, cascade, tout plier et tout fermer.
- **Écrans pixel** : zoom manuel supprimé, taille déterminée par la carte avec un facteur entier sans flou ; lecture synchronisée à 24 fps.
- **Optimisation des grands projets** : arbres et nœuds mémoïsés, contenu logique monté seulement pour les cartes proches de la vue, index de nœuds par module.
- Corrections de rendu : focus de sélection dans un même module, pliage des nœuds profonds, validité du dépôt, recherche Ctrl+F sans agrandir la carte, flèches et vues de la LED.

## Installation

1. Télécharger `Sapphire3-0.1.0-beta.2-windows.zip`.
2. Extraire l'archive dans un dossier accessible en écriture.
3. Lancer `Sapphire3.exe`.

Aucune installation de Node.js n'est nécessaire. Windows 10/11 avec WebView2 est requis.

## Fichiers

Le ZIP contient `Sapphire3.exe`, `resources.neu`, `updater.ps1`, `VERSION.txt`, les notices d'utilisation et le dossier `licenses/` avec les licences des composants distribués (React, Lucide, KaTeX, Neutralinojs, libtrashcan).

## Limites connues

- Les sauvegardes `.backup-1.sp3` à `.backup-3.sp3` ne sont créées que lors d'un enregistrement direct d'un fichier déjà existant ; l'autosauvegarde et « Enregistrer sous » ne les font pas tourner.
- Le moteur déporté couvre la simulation, le debug, la transpilation et les vérifications ; les mutations structurelles du document gardent une analyse synchrone pour renvoyer immédiatement leurs diagnostics.
- Les lambdas ont un corps expression unique : pas d'affectation, de boucle ou de `return` interne ; elles ne sont pas génériques et l'adresse de leurs paramètres n'est pas prise. Les captures sont en lecture et suivent les règles de fermeture de chaque backend dans les boucles.
- L'export SVG n'inclut pas les cartes écran, jauge et LED.
- Les positions des fenêtres flottantes et l'ordre de rangement ne sont pas persistés.
- Le debug d'un projet très long atteint la limite mémoire de l'historique des états.
- Lorsqu'une séquence d'écran sans cycle relance la simulation, seules les images d'écran, de jauge et de LED sont remplacées ; la trace de nœuds et la sortie du panneau restent celles du premier Run.
- Les pointeurs sont transpilés en JavaScript et Python par émulation ; les cartes Screen/Gauge/LED restent non transpilables.
- Les cibles C, C++ et Java sont présentes mais désactivées.
